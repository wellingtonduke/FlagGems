# 张石健20261108实验报告

7bca 严格 FP32 推理的 MUSA FlagGems 算子组合优化

最终组合在 MTT S5000 上平均用时 **111.89 秒**，绝对 MFU **5.06%**，相对 H100 原生 MFU **40.55%**，原始吞吐为 H100 原生的 **17.55%**。H100 原生平均 **19.64 秒**，绝对 MFU **12.48%**。同一分母下，此前 110 组合的三种子均值为 122.45 秒、相对 MFU 37.05%。本轮耗时降低 8.62%，相对 MFU 提高 3.50 个百分点。此前成绩与本轮来自不同 MUSA 节点，同卡单种子筛选也确认了主要收益。

50% 要求 MUSA 平均用时降到 **90.74 秒**。距目标还有 **21.16 秒**，需要在当前基础上再减少 **18.9%** 的耗时。

## 先读实验范围

本轮运行的是已训练模型的推理，模型权重全程固定。种子决定随机采样从哪里开始，同一输入换种子可能得到不同的候选结构。三种子各跑一次会输出 15 个候选。坐标审计里的 35 个结构计入同种子的重复运行，共 7 次完整预测，每次 5 个候选。H100 和 MUSA 对照时，对应运行使用同一份受控的随机流。

## 模型怎么跑，FlagGems 改在哪一层

7bca 用的是 Protenix Base Default v1.0.0。主干把输入整理成两类表示，一类描述单个 token，一类描述 token 两两之间的关系。48 层 Pairformer 更新这些表示，结果给扩散模块作条件。每个扩散步从当前带噪的原子坐标出发，先由原子编码器汇总到 token，再经 24 层扩散 Transformer，最后由原子解码器把信息送回原子坐标。200 步结束后，置信度头给候选结构打分。主干和扩散都会反复执行矩阵乘、归一化和门控，扩散里还有一些只依赖主干结果的计算，适合跨步复用。层数和预算取本次冻结配置。 [本轮模型配置](data/protocol.json) · [Protenix 主干](https://github.com/bytedance/Protenix/blob/main/protenix/model/modules/pairformer.py) · [Protenix 扩散模块](https://github.com/bytedance/Protenix/blob/main/protenix/model/modules/diffusion.py)

```text
输入特征 → Pairformer 主干 → 单 token 特征、token 对特征
                              ↓ 作为条件送入扩散模块
每个扩散步  带噪坐标 → 原子编码器 → token Transformer → 原子解码器 → 更新坐标
            下一个扩散步读取更新后的坐标，并使用该步的噪声等级
200 步后    输出结构 → 置信度头打分
```

从代码上看，替换发生在三个位置。第一种是**换后端实现**，模型照常调用批量矩阵乘，由 MUSA 注册把 `bmm` 分派给仓库后端。第二种是**改模型调用**，把 `SiLU(a)` 和乘 `b` 两次调用改成一个融合调用。第三种是**减少重复工作**，在扩散层保存本次预测中不变的中间量，在 FlagGems 的 Mul 启动代码中缓存布局信息。三种改法分别影响内核内部怎么计算、需要启动几个内核、同一份数据要准备几次。 [接入代码](code/repository_adapter.py)

## 从指定仓库启用的两项实现


### BMM，替换批量矩阵乘的 GPU 实现

一次 BMM 会并行算多对矩阵。比如追踪中的一组输入为 `[128, 234, 234]` 和 `[128, 234, 117]`，即 128 对矩阵分别相乘。通用对照走通用 FlagGems BMM，110 显式接入仓库的 MUSA 实现。这个实现把每个输出矩阵切成小块，不同 GPU 程序实例负责不同块。每个实例沿乘法的共同维度分段读取数据并累加。后端按矩阵尺寸选择分块配置，在并行度、数据搬运和每块的资源占用之间取舍。最终运行走 **FP32 FMA** 路径，关闭 TF32。该实现会在需要时把输入转成连续布局，仍可能有拷贝开销，整次预测计时已包含这部分。 [实际 BMM 源码](code/bmm_musa_overlay.py) · [输入形状和内核追踪](data/execution_audit.json)

前期同一张 GPU 7 上只开 BMM，种子 101 的热态整模型耗时从 **124.314 降到 122.801 秒**，省 **1.22%**。本轮完整追踪中确认执行了 **5,092 次** BMM。该百分比描述整模型的变化，现有对照没有进一步拆出每种矩阵形状的内核耗时。 [前期同卡对照](data/前期组合对照.md)

### SiLU×Mul，把门控中的两个逐元素操作合并

Protenix 的 `Transition` 和 `ConditionedTransitionBlock` 会做两路线性投影。一路生成门控值 `a`，另一路生成内容 `b`，随后用 `SiLU(a) * b` 把两路合起来。基础路径分两次执行，先运行 SiLU，再由乘法内核读回激活结果。改动后，模型显式调用注册到 MUSA 的 `flaggems_protenix::silu_and_mul`，同一个内核读入两个输入、完成逐元素计算，只写出乘积。这样省掉一次内核启动和一轮中间结果的写入、读回。融合函数在基础版 FlagGems 源码里也有，这次的改动是把它接到模型的两类门控模块。线性投影仍各自计算。 [模型接入代码](code/repository_adapter.py) · [FlagGems 融合实现](code/silu_and_mul.py)

本轮完整追踪确认融合内核执行 **7,567 次**。前期 GPU 7 上，在 BMM 已启用时加入融合，热态整模型耗时从 **122.801 降到 122.234 秒**。两项合用比同卡通用对照省 **1.67%**。另一张卡上单开融合也测得 **0.51%** 的整模型省时，卡间结果分别以各自的 000 为参照。 [前期同卡对照](data/前期组合对照.md)

## 本轮在 110 上新增的三项替换

### 扩散条件复用，把跨步重复计算改成每次预测内缓存

每个扩散步的坐标和噪声等级都在变化。已经算好的静态原子条件，以及从 pair 特征投影得到的注意力偏置，在这条运行路径里可复用。偏置可以理解为加到注意力分数上的一份先验关系。原路径每步重复准备静态原子条件，并对相同的 pair 特征做归一化、Linear 和维度排列。本轮把这部分提取成首次计算、后续读取，且在该路径复用只读的 pair 输入，省掉相应的复制。当前步的坐标投影和受噪声等级影响的计算仍逐步运行。

缓存作用域是一整次 `predict`。代码核对输入的存储地址、形状、步长、设备、数据类型及版本计数，并检查缓存结果是否被就地修改，预测结束后释放这次缓存。每次主计时预测中，原子条件计算 **1 次**、复用 **199 次**，pair bias 计算 **30 次**、复用 **5,970 次**。未命中时实际执行 FlagGems 的归一化和 Linear。MUSA 同卡筛选中，**122.28 → 119.49 秒**，省 **2.79 秒**。 [实现](code/diffusion_reuse.py) · [注册和追踪记录](data/execution_audit.json)

### Mul 元数据缓存，把反复上传布局改成直接复用 GPU 上的描述

通用 Mul 路径支持广播和非连续输入。内核需要一份整数表来知道输出形状、两个输入和输出的步长。步长决定某一维的索引加一时要跨过多少个元素。旧启动代码每次都用这些整数在 GPU 上构造一份新表，重复走张量创建及主机到设备的数据传递。新代码按**完整布局、设备和执行流**保存这张表，同类调用直接传已有描述。输入数值仍由同一个乘法内核读取并相乘。这个改动减少的是频繁启动内核前的准备开销。

主计时预测里每次命中 **20,502–20,505 次**。在已开启扩散复用时，加入缓存使耗时 **119.49 → 112.03 秒**，再省 **7.46 秒**，是本轮同卡筛选里最大的单项收益。这个差值来自完整预测，当前记录没有进一步拆开 CPU 创建和拷贝各占多少。 [启动代码改动](code/mul_metadata.py) · [种子 101 命中计数](data/mul_metadata_seed101.json)

### 原子聚合计数，用逐元素夹取替换布尔索引赋值

原子聚合求均值时，要把分母中的零计数抬到 1。旧代码用 `count[count < 1] = 1`，先找出满足条件的位置，再写这些位置，形成一份长度随数据变化的索引。新代码用 FlagGems 的 `clamp_min_(count, 1)`，让一个逐元素内核直接比较和写回，效果仍是把低于 1 的计数抬到 1。这样可以省掉构建索引和相关的同步点。本轮完整追踪确认夹取内核执行 **201 次**。叠加到已有缓存的配置后，耗时 **112.03 → 111.60 秒**，单种子观测约省 **0.43 秒**。这也移除了图捕获遇到的一处索引路径障碍。 [替换代码](code/scatter_floor.py) · [实际执行审计](data/execution_audit.json)

## 复测协议与结果

Base Default v1.0.0，7bca，10 cycles、200 steps、5 samples，种子 101、203、307，严格 FP32，关闭 TF32，核对两端权重 SHA256、冻结特征和逐步随机流记录。H100 原生与 MTT S5000 上的 MUSA FlagGems 分别使用通过占用检查的单卡。正式计时取预设的 `repeat2`，测同步的 `predict`，含预测内部数据搬运和共同的 CPU 随机流控制，排除模型加载、输入深拷贝、结果写盘及额外阶段计时。公开归档保留两端逐次预测耗时。

| 种子 | H100 原生 (s) | MUSA FlagGems (s) |
|---|---:|---:|
| 101 | 19.525 | 111.700 |
| 203 | 19.836 | 112.012 |
| 307 | 19.549 | 111.968 |
| 平均 | 19.637 | 111.893 |

MUSA 共执行七次完整预测。种子 101 的首个追踪调用为 136.64 秒，后两次为 111.77 和 111.70 秒。种子 203 和 307 各自第一次调用为 170.72 和 176.14 秒，其开销来源待拆分，原始值保留。`repeat2` 三次之内最大相差 0.31 秒。H100 首次启动曾因旧目录缺少参考审计文件中断，改用已保留的参考文件后重跑成功，首次中断日志单独保留。

三种子合计采用 492,431,642,818,068 模型 FLOPs。绝对 MFU 按 FLOPs 除以累计秒数与 FP32 峰值的乘积，峰值取项目硬件表的 H100 67 TFLOPS、S5000 29 TFLOPS。相对 MFU 以两端的绝对 MFU 相除，等价于原始吞吐比乘以 67/29。模型 FLOPs 使用共同口径，绝对 MFU 表示这项模型工作相对理论算力的有效利用率。

## 组合筛选

以下均为 MUSA 同卡、种子 101、同预算的 `repeat2`。筛选值用于决定组合，最终成绩用上面的三种子复测。

| 组合 | 秒 | 结论 |
|---|---:|---|
| 仓库 110，BMM 和 SiLU×Mul | 122.28 | 同卡参照 |
| 110 + 扩散静态特征与 pair bias 复用 | 119.49 | 节省 2.79 秒 |
| 复用 + 打包投影 | 119.64 | 未观察到加速 |
| 复用 + 通用 Mul 的形状与 stride 缓存 | 112.03 | 再节省 7.46 秒 |
| 上一组合 + `clamp_min_` 计数下限 | 111.60 | 选中 |
| 选中组合 + MUSA Graph | 113.66 | 坐标通过，含图捕获的整次预测更慢 |

同卡筛选中，本轮三个新增改动合计将 110 的耗时从 **122.28 降到 111.60 秒**，省 **10.68 秒**。前期 110 相对 000 的 1.67% 和本表相对 110 的收益分别来自各自的同卡对照，正式 MFU 仍采用三种子复测和 H100 原生分母。

**打包投影**尝试把对同一份输入的 Q、K、V 线性投影合成一次更宽的 FlagGems Linear，再按列切回三份结果。对于查询和键值输入不同的情形，只合并 K、V。扩散门控的两路投影也试了同样的合并。这样可以减少启动次数，矩阵形状和切分后输出的步长也随之变化。实测 **119.49 → 119.64 秒**，没有观察到整模型提速。 [投影打包实现](code/packed_projections.py)

**MUSA Graph** 把一次固定形状的扩散步捕获成可重放的 GPU 工作序列。后续每步更新坐标和噪声等级的输入缓冲区，再重放已有序列，以减少 CPU 逐个提交内核的开销。三次试验分别碰到 Mul 元数据主机至设备拷贝、布尔索引内部 `nonzero` 的拷贝，以及隔离容器内 MUPTI 不可用。最终用设备 Event 和同输入的普通执行输出复核，一次捕获、200 次重放。两次抽查为 328.97 和 327.55 ms，扩散步输出相对普通执行最大绝对差为 1.17e-5。计入预测内部的预运行、捕获、动态输入拷贝及输出复制后，图版本 **113.66 秒**，普通执行 **111.60 秒**，最终选普通执行。 [图重放实现](code/diffusion_graph.py) · [重放设备计时](data/graph_probe.json)

单独一次阶段追踪中，110 的 Pairformer 和扩散分别为 43.25 和 76.15 秒，扩散内的 token transformer 为 60.45 秒。加入复用和 Mul 元数据缓存后分别为 41.36、67.98、56.96 秒。后一个数字属于扩散内部，不能与扩散耗时相加。这个阶段仍是最大的已定位开销。若只从该阶段追回整轮的 21.16 秒，需节省约 37% 的阶段时间，且要用独立的热态整模型计时复核。
